# Requirement: On-Device Video Summary via iOS Shortcuts + ChatGPT App

## 1. Context

The YouTube Gate app already plays videos and can fetch closed captions. The next feature is a
**"Summarize" button** that turns a video's captions into a summary, suitable for saving to the
second brain.

Instead of calling an LLM API from a server (API keys, hosting, cost), this feature uses
**local app-to-app communication on iPhone**:

```
YouTube Gate app ──(clipboard + URL scheme)──▶ iOS Shortcut ──▶ ChatGPT app ("Ask ChatGPT")
        ▲                                                            │
        └──────────────(x-callback-url / clipboard)──────────────────┘
```

No server component, no OpenAI API key. The user's existing ChatGPT iPhone app and subscription do the work.

## 2. Goals

- One tap in the app starts the summary flow.
- Summary is generated by the ChatGPT iOS app via its Shortcuts action.
- Summary ideally returns to the YouTube Gate app automatically; opening the ChatGPT app instead is an acceptable fallback.
- Zero backend changes and no secrets stored in the app.

## 3. Non-Goals

- Android support.
- Calling the OpenAI API (or any LLM API) directly.
- Transcript fetching logic (assumed to already exist or be built separately).
- Automatic saving to the second brain (a follow-up; this feature just needs to hand the summary back).

## 4. Open Question to Resolve First

**What is the app's platform?** The approach differs:

| App type | Launch shortcut | Receive result back |
|---|---|---|
| Native iOS (Swift/SwiftUI) | `UIApplication.shared.open(url)` | Register a custom URL scheme; read clipboard on return |
| PWA / web app in Safari | `window.location.href = url` | `x-success` back to the web URL with a query param, or read clipboard on focus |
| React Native / Expo / Capacitor | `Linking.openURL(url)` | Deep link handler + clipboard read |

Claude Code should inspect the repo, confirm the platform, and pick the matching path before implementing.

## 5. Functional Requirements

### FR-1: Summarize button
- Visible on the video screen when captions are available; disabled or hidden otherwise.
- On tap:
  1. Build the payload (FR-2).
  2. Write the payload to the system clipboard.
  3. Open the shortcut URL (FR-3).

### FR-2: Payload
- Plain text: a short metadata header (title, channel, URL) followed by the caption text with timestamps stripped.
- The **prompt lives in the Shortcut, not the app**, so it can be tuned without redeploying. (Optional: app may prepend a prompt override if a setting is filled.)
- Guard against very long transcripts: if the text exceeds a configurable limit (default ~100k characters), truncate with a visible note, or warn the user.

### FR-3: Invoke the shortcut
- Use the x-callback-url form so control can return to the app:

```
shortcuts://x-callback-url/run-shortcut
  ?name=YTGate%20Summarize
  &input=clipboard
  &x-success=<app-return-url>
  &x-cancel=<app-return-url>?status=cancel
  &x-error=<app-return-url>?status=error
```

- Never pass the transcript in the URL (length limits); always `input=clipboard`.
- Shortcut name must be configurable in app settings (default: `YTGate Summarize`).

### FR-4: The Shortcut (built manually in the Shortcuts app)
Deliver step-by-step setup instructions (and a screenshot-free text description) in `docs/shortcut-setup.md`:

1. **Receive** text input; if none, get Clipboard.
2. **Text** action:
   ```
   Summarize this YouTube video transcript.
   Output: a 2-sentence TL;DR, 5–8 key points, and notable takeaways or action items.
   Keep it concise and in plain markdown.

   [Shortcut Input]
   ```
3. **Ask ChatGPT** (ChatGPT app action) with the text above. "Open in app" = off for the return-to-app flow.
4. **Copy to Clipboard** with the ChatGPT response.
5. Shortcut ends; iOS follows `x-success` back to the app.

Variant B (fallback): "Open in app" = on, so the user reads and continues the chat inside ChatGPT. No return path in this variant.

### FR-5: Receive the summary
- When the app is reopened via the `x-success` URL:
  - Read the clipboard.
  - Sanity-check it: it must not equal the original payload (which would mean the shortcut failed silently).
  - Show the summary in a sheet/panel under the video, with **Copy**, **Retry**, and **Save to second brain** (stub OK) actions.
- On `x-cancel` or `x-error`: show a non-blocking message with a Retry option.
- If the app regains focus with no callback within a reasonable window, offer a "Paste summary" button as a manual recovery path.

### FR-6: Settings
- Shortcut name.
- Mode: `return-to-app` (default) or `open-in-chatgpt`.
- Max payload length.
- A "Test shortcut" button that sends a tiny sample text end to end.

## 6. Non-Functional Requirements

- **Privacy:** transcript leaves the device only via the ChatGPT app. The app itself makes no network calls for this feature.
- **Clipboard hygiene:** after reading the result, optionally clear the clipboard (setting, default off). Handle the iOS "Allow Paste" prompt gracefully.
- **Resilience:** the flow must fail visibly, never silently. Every failure path ends with a clear message and a Retry.
- **No secrets** in code or config.

## 7. Known Constraints and Risks to Verify

- The **Ask ChatGPT** action's exact name, options, and whether it works without opening the app may vary by ChatGPT app version. Verify on-device first.
- iOS may show a paste permission prompt each time the app reads the clipboard.
- iOS may briefly show the Shortcuts app during the run; this is expected.
- Web apps/PWAs: `x-success` returning to a Safari PWA can open a Safari tab rather than the installed PWA. Test this specifically; if it's unreliable, use the "Paste summary" recovery flow as the primary receive path.
- ChatGPT usage limits on the user's plan apply.

## 8. Acceptance Criteria

1. With the shortcut installed, tapping **Summarize** on a video with captions produces a summary visible in the app (return-to-app mode) with no more than one system prompt to confirm (e.g., Allow Paste).
2. In `open-in-chatgpt` mode, the summary appears in the ChatGPT app with the prompt applied.
3. With the shortcut missing or misnamed, the app shows a helpful error that links to setup instructions.
4. Cancelling the shortcut returns to the app with a cancel message and Retry.
5. A 60-minute video transcript works end to end (or truncates with a clear notice).
6. `docs/shortcut-setup.md` lets a user build the shortcut from scratch in under 5 minutes.

## 9. Suggested Implementation Order

1. Confirm the app platform (Section 4).
2. Build the shortcut by hand and test it from the Shortcuts app with pasted text.
3. Test launching it via `shortcuts://x-callback-url/...` from Safari with a dummy return URL.
4. Implement FR-1 to FR-3 (send side).
5. Implement FR-5 (receive side) and the recovery path.
6. Add settings (FR-6) and the setup doc.
7. Wire "Save to second brain" in a follow-up.
